# תכנון בדיקות MVP4: סטטוס שבועי

עודכן: 25.10.2026 (גרסה 2, לפי PRD 0.4 סעיף 3.7 ו"טיוטת סעיף סטטוס MVP4" מ-25.10.2026). MVP4 עדיין לא נבנה, ולכן זה תכנון מראש: כל מקרה בדיקה (TC) במצב "לא הורץ". אחרי שהפיתוח מוזג לטסט, מריצים לפי המסמך ומעדכנים בדוח. נכתב כך שבודק אחר יוכל להריץ אותו לבד.

מקורות: PRD (2.4 ב', 3.7, 4.2, נספח 5.5), טיוטת סעיף הסטטוס, תפיסת הפתרון (6.4), מפרט המסכים. **המוקאפ ומפרט המסכים טרם עודכנו** (הם עדיין מציגים "הורדת תמונה" וכניסה מ"הכנת תוצרים"). בכל סתירה, ה-PRD קובע, וצעדי הלחיצה כאן לפי ה-PRD. אחרי עדכון המוקאפ נתאים את שמות הכפתורים.

## מה נכלל ב-MVP4

1. **פרסונה אחת, "יוצר התוכן (owner)"**: אבי ואשתו, באותן הרשאות. כל owner מאשר. שלי אינה מכינה, מאשרת או משתפת סטטוס. הלשון בניהול ניטרלית.
2. **כניסה מרשימת הפוסטים** בניהול: כפתור "סטטוס" ליד הפוסט. (בלי MVP2 ובלי MVP3.)
3. המערכת מציעה **שתי חלופות** מאותה גרסת פוסט: כל אחת 3 עד 6 כרטיסי טקסט, עד 3 משפטים בכרטיס, **משפטים מהפוסט כלשונם**, בלי תמונה.
4. **תיקון בלי טקסט חופשי**: החלפת משפט במשפט אחר מהפוסט, מחיקת כרטיס, שינוי סדר.
5. **שני אישורים**: אישור תוכן ("התוכן נכון") שלא מציג דבר, ואחריו אישור פעולה שמציג בדיוק מה יקרה (פוסט וגרסה, חלופה, יעדים). רק אישור הפעולה מציג את הסטטוס באתר.
6. **העתק** לכל כרטיס, ו**שתף** כשהטלפון תומך. ההעלאה לוואטסאפ ידנית, ויוצר התוכן מסמן **"שותף בוואטסאפ"**. הסימון מוצג ברשימת הפוסטים בעמודה "מצב סטטוס".
7. **מצב נפרד לאתר ולוואטסאפ.** כישלון ביעד אחד לא גורם לכפילות ביעד השני.
8. שינוי בפוסט **או בסטטוס** אחרי האישור מבטל את האישור ומסמן "נדרשת בדיקה". הסטטוס **מוסתר באתר** עד אישור מחדש (הצעה ב-PRD). מה שכבר שותף בוואטסאפ נשאר שם.
9. באתר: הסטטוס אחרי טקסט הפוסט (נייד), בעמודה הצדדית (מחשב), ובעמוד הבית לפוסט האחרון. פוסט בלי סטטוס מאושר: **האזור לא מוצג כלל**. כניסה מהסטטוס לפוסט נספרת בדוח השימוש כערוץ "סטטוס".
